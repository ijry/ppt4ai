# 删除版式设计

> 状态：已实现（2026-09-22，模型 + standalone + UI）
> 日期：2026-09-22

## 1. 目标

路线图 §9 母版编辑器:删除版式。engine `deleteLayout`,带占用与"母版至少留一个版式"守卫。

## 2. 关键决策

**决策 1：两条硬性守卫**

- 有幻灯片仍在用该版式 → 拒删(会让页的继承链落空)。
- 它是其母版下唯一的版式 → 拒删(母版必须至少有一个版式)。
两者皆以清晰错误抛出;否则从 `document.layouts` 删除,可撤销。

**决策 2：standalone 删除;源写回安全保留(核实修正)**

standalone `createPptx` 枚举模型版式,删掉的版式不再写出(测试验证只剩其余版式)。**源写回不删源版式部件**——探针核实:importer 只导入被幻灯片引用的版式,导出时“模型里没有版式 X”在“用户删了它”与“它本是源包里未被任何页引用、importer 从未 surface 的版式”之间无法区分,删源部件会误毁合法未用版式。所以源写回保留该部件(母版仍列它、rels 仍指它,包内部一致),`deleted-layout-writeback.test.ts` 固定此安全降级。此前本文写“孤儿清理会移除”不准确,已据探针更正。

## 3. 测试策略（TDD）

- **engine**（`set-slide-layout.test.ts`,+4）:切走后删未用版式+撤销;拒删在用;拒删唯一;缺失抛错。
- **standalone**（`deleted-layout-standalone.test.ts`,1）:删后只写剩余版式部件。
- **playground**（wiring,+2）:复制后删新增版式;拒删当前页在用的版式。
- **回归**：全量 2495 项。

## 4. 已知限制

- 源写回保留被删版式的源部件(见决策 2:无法与合法未用版式区分,保留是安全侧)。要在源写回也真正抹掉需要显式“用户删除”信号,属独立设计题。standalone 路径以模型为准,完全干净。
