# 描边宽度与线型写回设计

> 状态：待实现（2026-09-03）
> 日期：2026-09-03

## 1. 目标

让写回真正写出 `a:ln/@w` 与 `a:ln/a:prstDash`。这两个字段从描边宽度（`3051297`）与虚线（`5a90134`）两刀起就能读、能画、能从 standalone 写出，但**范围写回从不写它们** —— 于是模型能持有一个导出端拒绝输出的值。

## 2. 探针结果（实测）

源里 `<a:ln w="12700" cap="rnd">…<a:prstDash val="dash"/></a:ln>`，导入后把模型改成 `strokeWidth=76200`、`strokeStyle='dot'`，再导出：

```
imported : w=12700 style=dash
after    : <a:ln w="12700" cap="rnd"><a:solidFill><a:srgbClr val="203864"/></a:solidFill><a:prstDash val="dash"/></a:ln>
```

**输出与源逐字节相同 —— 两处编辑都静默丢失。** 不报错、不警告。

## 3. 这与渐变那刀是同一个陷阱的另一半

渐变那刀的教训是「**读而不写**会破坏文件」：导入端一旦产出 `fill`，只认 `solidFill` 的比较会把 `gradFill` 覆盖成纯色。

这一刀是对称的另一半：「**能读能存却不写**会静默丢编辑」。模型字段存在、校验通过、画布如实渲染，唯独导出端不认 —— 于是任何改动它的路径都会在导出时无声回滚。

**今天还不可从公开 API 触达**（engine 没有对应命令，`grep "type: 'set"` 只有九条，无 stroke 相关），所以现在修是在缺陷可达之前补上。加命令之前先修写回，顺序不能颠倒 —— 否则先加的命令会立刻带着「编辑会消失」的行为发布。

## 4. 关键决策

**决策 1：`w` 与 `prstDash` 各自独立比较，不并进 `fillsEqual`**

`fillsEqual` 比的是 `Fill`（颜色与渐变）。宽度与线型不在 `Fill` 上（它们是元素的兄弟字段 `strokeWidth`/`strokeStyle`），所以三者**各产出各自的替换**：颜色变了只换填充节点，宽度变了只换 `w` 属性，线型变了只换 `prstDash`。

**否决把三者合成「整块重写 `<a:ln>`」** —— 那会丢掉 `cap`/`cmpd`/`algn` 这些未建模属性，正是描边宽度那刀专门加断言守住的东西。范围写回的既有纪律是「只动认识的那一处」。

**决策 2：`w` 缺失与 `w="0"` 必须区分**

OOXML 里 `w` 省略意味着「继承主题线宽」，`w="0"` 是明确的发丝线。模型里 `strokeWidth` 为 `undefined` 与 `0` 也是两回事（描边宽度那刀已经有 `w="0"` 的导入测试）。所以：

- 模型有值、源没有 → 插入 `w` 属性
- 模型有值、源有不同值 → 替换属性值
- 模型无值、源有值 → **删除 `w` 属性**（模型说「不知道宽度」，保留源值等于让文件与模型不一致）
- 两边都无 → 不动

**决策 3：`prstDash` 是子元素，位置按 ECMA-376 序列排在填充之后**

与 standalone 那刀同一条规则。写回时：

- 源有 `prstDash` 且模型线型不同 → 替换该节点
- 源有 `prstDash` 且模型是 `solid`/无 → **删除该节点**（`solid` 不进模型，删除等于回到缺省）
- 源无 `prstDash` 且模型有非 solid 线型 → 插在填充节点之后；若无填充节点，插在 `<a:ln>` 内容起始处

**决策 4：源里没有 `<a:ln>` 时，新建的那个要带上宽度与线型**

`strokeReplacements` 现有的「无 `line` 就插入 `<a:ln>` + 填充」分支，现在还要带 `w` 与 `prstDash`。否则「给一个原本无轮廓的形状设颜色和宽度」只有颜色写出去。

**决策 5：未编辑必须逐字节不变，这条是本刀的主要风险**

三处独立比较意味着三个「相等就不产生替换」的判断。任何一处判等写错都会让**每次导出都重写**未编辑的文件 —— 那正是子坐标空间那刀（`da350ce` 记录）栽过的坑：重映射后每个子元素都「看起来被编辑过」。因此断言里既有「改了要写出」也有「没改必须逐字节相同」，两侧都钉。

## 5. 契约（增量）

无对外契约变化。`strokeReplacements` 内部扩展，`exportPptx` 行为对未编辑文档不变。

## 6. 测试策略

- **宽度**：改宽度写出新 `w` 且 `cap="rnd"` 与 `prstDash` 原样保留；源无 `w` 时插入；模型无值时删除 `w`；`w="0"` 与无 `w` 区分开
- **线型**：改线型替换 `prstDash`；改成 solid 删除该节点；源无 `prstDash` 时插在填充之后
- **组合**：颜色、宽度、线型同时改，三处都写出且未建模属性保留
- **新建**：源无 `<a:ln>` 时新建的元素带 `w` 与 `prstDash`
- **未编辑**：只读导入再导出逐字节不变；只改文本时 `<a:ln>` 逐字保留
- **回归**：现有 1271 项测试，尤其描边宽度与虚线两刀那些「写回一行未改」的断言 —— 它们断言的是**未编辑时**保留，本刀不改变那个行为

## 7. 已知限制

- 仍然没有 engine 命令与工具栏控件，所以从 UI 还改不了 —— 但模型改动现在能正确导出，命令是下一刀且不再带缺陷
- `cap`/`cmpd`/`algn`/`join` 仍不建模，未编辑时保留、`<a:ln>` 被新建时不写出
- master/layout 的写回路径（`master-layout-writeback.ts`）有自己的 `strokeReplacements`，本刀不动它 —— 占位符的 `ElementDefaults` 至今不带宽度线型，没有可写的值
