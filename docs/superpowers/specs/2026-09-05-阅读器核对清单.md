# 阅读器核对清单

> 日期：2026-09-05
> 状态：待核对

## 1. 目的

本文档汇总所有设计文档中标注为**待阅读器核对**或**待决策**的项目。这些项目的实现基于 OOXML 规范的读法或合理推断，但因缺少阅读器（PowerPoint、Keynote、Google Slides 等）的实测验证，尚未确认与实际应用行为一致。

阅读器可用后，按本清单逐项核对，确认或修正当前实现。

## 2. 核对项

### 2.1 径向渐变停靠点方向（`a:path`）

**来源**：`2026-09-04-radial-gradient-design.md:77`

**当前实现**：`a:fillToRect` 的中心是渐变的起点（offset 0），半径取到最远的角。语义为「第一个停靠点落在收敛矩形的中心，最后一个落在形状边界」。

**待核对**：`l=t=r=b=50000`（收敛到中心点）配「浅色在前、深色在后」的停靠点，PowerPoint 画出来是否为中心浅、边缘深？

**核对方法**：
1. 手搭 `a:gradFill` + `a:path path="circle"` + `a:fillToRect l="50000" t="50000" r="50000" b="50000"`
2. 停靠点为 `<a:gs pos="0"><a:srgbClr val="FFFFFF"/></a:gs>` + `<a:gs pos="100000"><a:srgbClr val="000000"/></a:gs>`
3. PowerPoint 打开，观察中心是白色还是黑色

**若不符**：反转 `gradientFocus` 返回的 `centre` 与 `radius` 在 `createRadialGradient` 中的顺序，或反转停靠点数组。

### 2.2 表格样式区域外边框只画在外沿

**来源**：`2026-09-04-table-style-inside-borders-design.md:39`、`:70`

**当前实现**：`wholeTable` 的 `top`/`bottom`/`left`/`right` 画在**每个单元格**的对应边上（即表格内部也有这些边框）。

**待核对**：PowerPoint 里 `wholeTable` 的 `top` 是否只画在表格最上沿，而不是每个单元格的上边？

**核对方法**：
1. 手搭表格样式 `<a:wholeTable><a:top><a:ln w="38100"><a:solidFill><a:srgbClr val="FF0000"/></a:solidFill></a:ln></a:top></a:wholeTable>`
2. 应用样式到多行表格，观察是否只有最上沿是红色，还是每行上边都是红色

**若不符**：修改 `regionBordersForCell`，让 `top` 只在 `row === 0` 时生效，`bottom` 只在 `row === table.rows - 1` 时生效，`left` 只在 `col === 0` 时生效，`right` 只在最右列时生效。

### 2.3 单元格文本边距默认值

**来源**：`2026-09-05-cell-text-framing-design.md`、`2026-09-05-cell-text-framing-record.md`

**当前实现**：`a:tcPr` 的 `marL`/`marR`/`marT`/`marB` 缺席时，导入/场景/绘制**不补默认值**，单元格文本紧贴边缘。

**待核对**：PowerPoint 是否对缺 `marL` 的单元格自动补 91440 EMU（0.1 英寸）左边距？`marR` 是否同样 91440？`marT`/`marB` 是否为 45720 EMU（0.05 英寸）？

**核对方法**：
1. 手搭表格，`a:tc` 不写 `a:tcPr`，或写 `<a:tcPr/>` 但不写 `@mar*`
2. PowerPoint 打开，测量单元格文本到边框的距离（选中表格 → 右键 → 设置单元格格式 → 文本框 → 内部边距，观察默认值）

**若需补默认值**：在 `parseTableCell` 或 `resolveTableCellStyle` 的 `cellBodyPr.insets` 后补 `?? {left: 91440, right: 91440, top: 45720, bottom: 45720}`；同时修改导出侧，让 `serializeTableCellXml` 在边距等于默认值时**不写**属性（避免往返后文件膨胀）。

**决策依据**：若阅读器确认有默认值，且用户反馈「表格文本贴边」是 bug，则补；否则保持当前行为（理由：手搭 `marL="0"` 的文档不应被覆盖，且补默认值会让所有既有表格的绘制结果变化）。

### 2.4 图案填充的线宽与间距

**来源**：`2026-09-05-pattern-texture-design.md`

**当前实现**：18 个线条族 `prst` 词按名字声明的方向绘制，粗细与间距取本项目自己的一组常量（`patternGeometry` 的 `patternRecipes`）：`lt` 线宽 1、基础 2、`dk` 3；间距基础 8、`nar` 4、`wd` 16、`lgGrid` 16。

**待核对**：Office 用 8×8 位图画每个图案，本项目的常量与它逐像素不同。名字声明的**相对关系**（`dkHorz` 比 `ltHorz` 粗、`narHorz` 比 `horz` 密、斜向的倾斜方向）已保证可见，但绝对尺寸是近似。

**核对方法**：
1. 手搭一页，同尺寸方块各用一个线条族预设填充（至少覆盖 `ltHorz`/`horz`/`dkHorz`/`narHorz`/`ltUpDiag`/`ltDnDiag`/`cross`/`diagCross`/`smGrid`/`lgGrid`）
2. PowerPoint 与 LibreOffice Impress 各打开一次，同缩放截图
3. 与本项目渲染结果并排比较：先看方向是否一致（若某个斜向反了，那是 bug 不是近似），再看密度排序是否一致，最后才看绝对尺寸

**若不符**：方向错→改 `patternLines` 的 `up`/`down` 分支；密度排序错→调 `patternRecipes` 的 `spacing`/`width`；仅绝对尺寸不同→按实测调常量即可，无需改结构。

**百分比族（`pct5`…`pct90`）另有一条**：已按名字里的百分比画成半透明前景压在背景上（`4926844`），**平均颜色对、点阵结构不画**。核对时在高缩放下截图比较：真实阅读器应能看到离散的点，本项目是平滑混色。若这个差异在实际使用中显眼，替代方案是按缩放级别切换（低缩放用混色、高缩放画点），但那要先有实测才值得做。

**装饰族仍待定**：`zigZag`/`weave`/`sphere`/`shingle`/`plaid`/`divot`/`trellis`/`horzBrick` 等词目前画前景纯色。核对时顺带记录这些词在阅读器里的实际样子，作为后续切片的依据。

## 3. 核对流程

1. **搭建测试文档**：按上述每项的「核对方法」手写最小 PPTX（可用 7-Zip 解包编辑 XML，或用脚本生成）
2. **阅读器打开**：PowerPoint 365 / 2021 / macOS 版本，观察实际绘制结果
3. **记录观察**：截图 + 文字描述，附在本文档对应项下
4. **修正实现**：若与当前实现不符，按「若不符」小节修改代码，补测试，提交时引用本清单对应项编号
5. **更新状态**：核对完成后，在原设计文档中删除「待阅读器核对」标注，本清单对应项标记为✅
